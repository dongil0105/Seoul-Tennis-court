표의 물리 면수는 v5 `courtCount`를 적용한 해석입니다. §4는 ‘셀 수 있으면 면수’라고 하지만 §10.1은 계산법을 확정하지 않아 숫자 기대값을 계약에 추가해야 합니다.
추가 경계: §10.1의 `opened=서버 표시 || 시각 경과`는 서버가 미래 항목을 opened로 주면 미래 hot도 만들 수 있습니다. 충돌 시 확인 상태로 처리하고 hot은 `0 <= 경과 < 2시간`으로 제한하세요.
정확히 2시간은 hot의 ‘안’과 cold의 ‘넘음’ 사이에 빠집니다. v5처럼 hot 미만·cold 이상으로 확정하고, 하루가 바뀔 때 재판정하세요.
상시 예약이 모두 마감되면 always 조건이 사라져 ‘미정’으로 바뀌는 것도 어색합니다. 현재 접수 여부와 별개로 알려진 예약 방식은 유지하되 자료에 근거가 없으면 추정하지 마세요.
공지 일정의 2시간 경과 삭제 후 실제 새 일정이 없을 때, 지난 공지 시각을 실제 ‘지난번 오픈’으로 기록하지 마세요. 실제 오픈 이력과 예상 이력을 구분해야 합니다.

## v5 대비 빠진 것

아래는 실제 삭제가 확정됐다는 뜻이 아니라, **스펙에서 유지가 명시되지 않았거나 접근 단계가 늘어난 항목**입니다.

- **오늘 열린 지 2시간 지난 예약(cold)**: v5는 오픈 일정에 ‘열림’과 코트 링크를 남깁니다. v6 모델에는 cold가 있지만 §5에는 표시 구역이 없습니다. “오늘 시작한 예약” 접힘 목록으로 유지하세요.
- **지난 오픈 날짜와 시각 여러 개**: v5 `pendHTML`은 최근 2개의 날짜·시각을 보여 줍니다. §4.2·5는 지난 날짜 하나만 제시합니다. 선우의 10.27 09:30·9.23 09:30처럼 “지난 예약 시작” 목록으로 보존하세요.
- **접수 중이 아닌 코트 전체**: v5는 full/ended/paused/unknown과 혼합 상태·각 예약 링크를 제공합니다. §5 ‘마감된’으로 축약하면 뜻이 달라집니다. “예약 상태별 코트 n건 보기”와 개별 상태를 유지하세요.
- **무료/유료·조명·운영 시간·요일·야간/주말 구분**: v5 picker는 이 정보를 조합해 표시합니다. ‘코트 버튼’만으로는 보존 보장이 없습니다. 특히 마루의 일반 무료와 조명 유료는 번호만 합치지 말고 선택지를 나누세요(v5는 무료 및 요금 혼재 시 유료 표기).
- **신청 마감과 이용 기간**: v5는 `until_kind`, `until_label`, `period`로 구별합니다. §5 ‘회차(이용 기간)’로 통일하면 선우 11.30 신청 마감이 사라집니다. 두 개념을 각각 표시하세요.
- **공지 일정 설명·정기 규칙**: v5 큰 카드에는 rule, 하단에는 실제와 다를 수 있다는 설명이 있습니다. 더보기로 옮기더라도 예상 일정 바로 옆 설명을 남기세요.
- **갱신 시각·오래됨·실패 후 이전 자료 안내**: v5는 서울시 20분 경과 표시, 반포 자체 시각·stale, 수동 갱신 실패 안내를 제공합니다. v6의 ‘12:30 기준’만으로 대체하지 마세요.
- **로딩·오류·빈 화면의 행동**: v5의 느린 초기 로딩 설명, 연결 실패 “다시 시도”, 서버 자료 미수신과 다음 일정 없음의 구분, JS 비활성 안내를 구체적으로 계승하세요. 목표에 이름만 나열돼 있어 구현 누락 위험이 있습니다.
- **반포 상세와 설정 유지**: v5의 날짜별 빈 코트, 시간대별 없음 안내, 이후 열리는 이용일, 예약 사이 마감 가능성 설명, 시간대 선택 저장·펼침 유지가 새 화면에서도 필요합니다.
- **설치·공유·알림 복구**: 기능은 남지만 더보기/알림으로 이동해 접근이 늘어납니다. v5의 아이폰 3단계 설치, 주소 복사, 권한 차단 해제, 등록 연결 확인·재시도, 테스트 결과 안내를 유지하세요.
- **새 알림 정리·필터·접근성**: v5의 새 알림 닫기, 중복 제거, 설정별 feed 필터, 확대 대응·동작 줄이기·초점 복귀·링크 설명은 새 디자인에 명시적으로 이식하세요. ‘최근 24시간 기록’이 v5보다 오래 보존되는 것인지도 정해야 합니다.
