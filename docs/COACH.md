# 스윙 코치 (`/coach`)

테니스 스윙 영상을 넣으면 선수 자세와 나란히 보여 주고, 동호인 눈높이로 "무엇을 하나 고치면 되는지" 알려 주는 화면.
빈 코트 찾기(`/`)와 같은 서버에서 화면 파일만 내려 준다. **분석은 모두 휴대폰 브라우저 안에서 돌고, 영상은 서버로 오지 않는다.**
`/coach` 응답에는 콘텐츠 보안 정책이 붙어 있어, 이 화면이 연결할 수 있는 곳은 우리 서버뿐이고 밖에서 가져오는 것은 위키미디어의 선수 사진뿐이다
(자세 인식 엔진에 들어 있는 구글 사용 통계 전송도 여기서 막힌다 — 브라우저로 확인했다).

## 쓰는 사람이 보는 흐름

1. **스윙 영상**(서브·포핸드·백핸드 한 번) 또는 **전체 영상**(랠리·경기)을 휴대폰 갤러리에서 고른다.
2. 스윙 영상: 종류(알아서/서브/포핸드/백핸드), 영상 속도(일반/슬로모션)를 고르고 분석.
   전체 영상: 볼 구간을 정하면 영상 속 사람들을 **웃옷 색**으로 묶어 사진으로 보여 준다 → 한 사람을 고르면 그 사람의 스윙만 찾아
   **잘 친 샷 / 아쉬운 샷**과 되풀이되는 문제를 모아 준다.
3. 결과: 임팩트·백스윙(트로피)·피니시 화면에 뼈대를 얹어 보여 주고, **나와 가장 닮은 선수 자세**를 옆에 둔다(겹쳐 보기 가능).
   점수, "가장 먼저 이것 하나", 나머지 조언, 잘하고 있는 것, 잰 값, (서브면) 내 타점에서 공이 들어가는 각도.
   각도·자세를 고치라는 조언에는 **그림**이 붙는다: 막대 인형 두 개로 '지금'(주황)과 '이렇게'(노랑)를 나란히 보여 주고,
   잰 값(예: 팔꿈치 151°)을 그림에 그대로 적는다. 옆모습(팔꿈치·무릎·타점 앞뒤·높이), 위에서 본 모습(어깨 턴·몸통 회전), 앞모습(서브의 팔–몸통 각).
4. 공이 어떻게 됐는지(네트·길게 아웃 등)를 알려 주면 라켓 면 조언까지 묶어 준다.
5. 결과 이미지를 공유하거나(장면 사진과 함께 / 뼈대만), 이 스윙을 **내 기준 자세**로 저장할 수 있다(선수·코치 영상을 분석해 저장해 두면 다음부터 그 자세와 견준다).
6. 종류(서브·포핸드·백핸드)나 임팩트 순간이 틀리게 잡혔으면 결과 화면에서 바로잡을 수 있다.

## 구조

```

  js/app.js                     흐름(고르기 → 분석 → 결과 → 공유), 전체 영상
  js/ui.js                      화면 바꾸기·시트·토스트·내 정보(기기 저장)
  js/pose.js                    영상 → 프레임별 자세(MediaPipe). GPU/CPU 중 빠른 쪽을 고른다
  js/track.js                   웃옷 색으로 사람 묶기·따라가기
  js/clean.js                   좌우 뒤바뀜·튀는 점 보정
  js/swing.js                   스윙 찾기, 서브/포핸드/백핸드 구분, 임팩트·트로피·백스윙 순간
  js/metrics.js                 자세 한 장의 수치 + 스윙 전체 수치
  js/advice.js                  수치 → 조언(규칙표), 대조군 찾기
  js/physics.js · physview.js   공 궤적(항력+마그누스), 들어가는 각도 계산기
  js/draw.js                    뼈대·겹쳐 보기·공유 카드
  js/figures.js                 조언에 붙는 그림(막대 인형으로 '지금 → 이렇게')
  data/reference.json           선수 사진에서 만든 기준 분포 + 대조군 표본(출처 포함)
  vendor/                       MediaPipe 엔진·모델(출처·라이선스는 vendor/README.md)
tools/coach/                    기준 자세 데이터를 만드는 도구(아래)

tests/js/coach_engine.test.mjs  엔진(합성 스윙) · tests/js/coach_physics.test.mjs  물리
docs/coach/                     조사 자료(연구 수치·출처)와 Codex 검토 기록
```

DOM 을 쓰지 않는 모듈(geom·clean·swing·metrics·advice·physics·track 의 색 계산)은 브라우저와 Node 에서 똑같이 돈다.
그래서 기준 데이터를 만들 때도, 테스트할 때도 앱과 **같은 코드**로 잰다.

## 어떻게 재나

- 자세: MediaPipe Pose Landmarker(관절 33곳). 스윙 한 번은 full 모델, 전체 영상을 훑을 때는 lite 모델.
- 공과 라켓은 보지 못한다. **치는 손목**이 타점을 대신한다. 화면의 수치는 손목 기준이고, 공 높이는 "손목 + 라켓" 범위로만 쓴다.
- 길이는 모두 '키의 몇 배'로 재고, 내 정보의 키로 cm 로 바꾼다.
- 스윙 찾기: 골반 기준 손목 속도의 꼭대기. 가만히 선 영상·걷는 팔 흔들림·인식 떨림은 최소 속도, 돌출도, 실제 이동 거리로 걸러 낸다.
- 임팩트 시각은 **어림**이다(서브: 손목이 가장 높은 순간, 스트로크: 손목이 가장 빠른 순간 직후).
  프레임 간격의 절반만큼은 알 수 없으므로, 그 사이 손목이 움직이는 거리를 **타점 위치 오차**로 같이 보여 준다
  (초당 30장 영상 ±15cm 안팎, 슬로모션 ±2~4cm). 조언은 이 오차보다 크게 벗어났을 때만 한다. 사용자가 한 장씩 옮겨 고칠 수 있다.
- 타점이 몇 cm 앞·뒤인지는 **옆에서 찍은 영상**에서만 잰다. 뒤에서 찍은 영상은 몸통·팔 각도 위주로 본다.
- 화면 위치를 견주는 값(점프 높이 등)은 **카메라를 고정**해 찍었다고 본다.
- 잰 것이 부족하면(임팩트 자세를 못 읽음, 팔다리가 거의 안 보임, 잰 항목이 4개 미만) **점수를 내지 않는다**. 못 잰 것을 '좋다'고 하지 않는다.
- 전체 영상은 30초 구간씩 훑어 스윙 시각만 남기고 프레임은 버린다(긴 영상에서 메모리가 늘지 않게). 재생 속도는 기기의 인식 속도에 맞춘다.
  찾은 스윙 중 가장 빠른 18개까지만 자세히 본다.

## 선수 기준 데이터 (`data/reference.json`)

- 원본: 위키미디어 공용(Wikimedia Commons)의 자유 이용 허가 사진 — 분류 `Service (tennis)`, `Forehand (tennis)`, `Backhand (tennis)` 와 그 하위 분류.
  유명 선수만이 아니라 투어·챌린저·퓨처스 선수 사진이 섞여 있다. 1970년 이전 사진·나무 라켓 시절 선수·어린이 사진은 뺀다.
- 규모(지금 들어 있는 것): 사진 2,046장을 읽어 477장 사용, 이름을 알아본 선수 209명, 성별 확인 95%(남 263 · 여 188), 대조군 표본 375개.
  스트로크 분류 사진에 더해, 선수 분류(알카라스·시너·사발렌카·가우프·오사카·페굴라 등)의 사진에서 서브 자세를 골라 넣었다.
  대조군 표본을 고를 때는 `tools/coach/players.json` 의 `priority` 선수(페더러·조코비치·나달·시너·알카라스·세레나 등)를 먼저 넣는다.
  선수 분포가 연구 수치와 맞는지 확인했다 — 예: 서브 임팩트 팔꿈치 160°(굽힘 20°, 문헌 20~30°), 팔–몸통 각 122°(문헌 101~111° ± 17),
  포핸드 임팩트 팔꿈치 123°(문헌 100~130°), 서브 트로피 팔꿈치 107°(문헌 85~107°).
- 만드는 법: 사진에서 앱과 같은 자세 모델(heavy)로 뼈대를 뽑고 → 스트로크·순간(트로피/임팩트/백스윙/피니시)을 자세로 가려 →
  순간별 **분포**(가운데값·흩어짐, 전체/남/여)와 **대조군 표본**(뼈대 + 사진 주소 + 저작자·라이선스)을 만든다.
  왼손잡이는 오른손 기준으로 뒤집어 넣는다. 다리가 잘린 사진은 윗몸 수치만 쓴다.
- 저장소에는 **뼈대 수치와 출처만** 있다. 사진은 화면에서 위키미디어 주소로 불러오고, 사진 밑에 저작자·라이선스·원본 링크를 적는다.
- 조언의 목표 범위는 "선수 분포"와 "연구 수치에서 잡은 기본 범위" 중 **더 너그러운 쪽**이다. 선수와 똑같이 하라고 하지 않는다.
- 대조군은 내 자세와 가장 닮은 자세 중에서, 선수 분포의 한가운데에 가까운(따라 하기 쉬운) 것을 앞에 둔다. 백핸드는 원핸드/투핸드가 같은 것을 먼저.
- 순간(트로피·임팩트 등)은 사진의 자세만 보고 자동으로 가린 것이다. 공이 보이지 않으니 정확히 그 순간이 아닐 수 있고, 화면에서도 그렇게 알린다.
- 선수 이름·성별은 `tools/coach/players.json` 이름표와 공용의 분류(예: `Ana Ivanovic in 2009` → 선수 분류의 `Female tennis players …`)에서 읽는다.

다시 만들기:

```bash
python3 tools/coach/commons_collect.py --out /tmp/commons \
  --seed "Service (tennis)=serve" --seed "Forehand (tennis)=forehand" --seed "Backhand (tennis)=backhand" --depth 2
tools/coach/make_reference.sh /tmp/commons /path/to/pose_landmarker_heavy.task
```

수집은 공용이 권하는 표준 썸네일을 천천히 받는다(원본·API 를 쓰지 않는다). 영상으로 움직임 전체를 뽑을 때는
`tools/coach/commons_videos.py` → `tools/coach/video_to_poses.mjs`.

### 영상 학습에 대해

- 유튜브 영상은 받지 않는다(약관·저작권). 대신 사용자가 **자기 휴대폰에 있는 선수·코치 영상**을 앱에서 분석한 뒤
  "내 기준 자세로 저장"하면 그 뼈대가 기준으로 들어간다(뼈대만 기기에 저장).
- 위키미디어 공용의 프로 경기 영상은 대부분 관중석에서 멀리 찍은 것이라 선수가 너무 작다. 그래서 선수 기준은 사진이 중심이다.

## 연구 수치

`docs/coach/serve_knowledge.json`, `docs/coach/ground_knowledge.json` 에 조사한 수치·선수 정보·흔한 실수와 출처가 있다
(요약은 같은 폴더의 `*_notes.md`). 논문 전문이 아니라 검색 요약에서 가져온 값이고, 기억에 의존한 값은 `memory`, 직접 계산한 값은
`computed`/`CALC` 로 표시돼 있다. 조언 문구와 기본 범위는 이 자료에서 왔다.

## 한계 (솔직하게)

- 라켓 면은 직접 재지 못한다. 결과(네트·아웃)를 알려 줬을 때만, 몸에서 잰 것과 묶어 면 조언을 한다.
- 공이 들어갔는지는 영상으로 판정하지 않는다. 전체 영상의 '잘 친 샷'은 자세 점수 기준이다.
- 성별은 영상으로 맞히지 않는다. 사람은 사진·옷 색으로 직접 고르고, 성별은 비교할 선수 분포를 고를 때만 묻는다.
- 사람이 화면에 작게 나오거나, 어둡거나, 카메라가 움직이면 정확도가 떨어진다. 화면에서 그렇게 알려 준다.
- **실제 휴대폰(iOS 사파리·안드로이드 크롬)에서는 아직 확인하지 못했다.** 헤드리스 크롬으로 끝까지 돌려 본 것이 전부다.
- 점수는 자세가 선수 분포에서 벗어난 정도를 줄인 값이지 실력 점수가 아니다.
