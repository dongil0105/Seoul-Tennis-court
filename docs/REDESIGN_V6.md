# 코트 오픈 v6 — 화면 전면 재설계 (설계 기준서)

> Claude(설계·구현)와 Codex(검토·독립 시험)가 함께 보는 기준이다.
> 화면 코드는 `app/static/dashboard.html` 한 파일(손으로 쓴 HTML·CSS·JS, 빌드 도구 없음).
> 서버 API(`/board`, `/refresh`, `/push/*`)와 서비스워커(`sw.js`)는 바꾸지 않았다.

## 1. 왜 다시 만들었나

사용자 의견: "전혀 직관적이지 않다."

- v5 는 **기능 순서**(다음 오픈 → 오픈 일정 → 접수 중인 코트 → 반포)로 길게 이어져, "내가 가는 테니스장은 어떻게 됐지?"에 바로 답하지 못했다.
- 구역마다 모양이 달랐다(펼치는 줄, 번호 타일, 표, 시간대 버튼). 반포만 완전히 다른 화면이었다.
- 알림 설정이 종 버튼 뒤 시트에 숨어 있었고, 테니스장마다 알림을 켜는 방법이 눈에 안 보였다.

## 2. 목표(의견이 갈리면 이 순서로 정한다)

1. **테니스장별로 본다.** 맨 위에서 테니스장을 고르면 그곳 정보만 나온다.
2. **어느 테니스장이든 같은 모양.** 카드 하나, 두 칸(`지금 예약` · `다음 예약 오픈`), 같은 순서의 구역.
3. **초등학생도 읽는다.** 색 + 점 + 짧은 말.
4. **정직하게.** 서울시 자료는 날짜별 남은 자리를 주지 않는다. `예약 받는 중`을 "빈자리 있음"으로 말하지 않는다.
5. **시판 앱처럼.** 아래 탭 3개, 카드, 일관된 버튼·글자 크기, 밝은/어두운 화면, 불러오는 중·빈 화면·오류 화면.

하지 않는 것: 서버 변경, 예약·결제 자동화, 서울시 예약 사이트 자동 접속(사람이 누르는 링크만).

## 3. 화면 구조

```
[위 줄]     코트 오픈 로고 · 이름                         [09:01 기준 · 새로 고침]
[홈 탭]     테니스장 고르기 줄(가로로 미는 버튼): 전체 | 대치유수지 | 마루공원 | 반포 | 서울숲 | 선우공원 | 잠원 | 장충 | 한남  (가나다순)
            (정보가 20분 넘게 오래되면 노란 띠 + 새로 고침)
            ├ 전체:  새 알림 띠 → "테니스장 6곳 [정렬 ▾]" → 테니스장 카드 6장 → 안내 한 줄 → 처음 쓰는 사람 안내
            └ 한 곳: ‹ 전체 테니스장 → 머리 카드(코트 그림 · 이름 · 지역과 바닥 종류 · 종 · 두 칸 · 새 알림 · [코트 예약 닫기]) → (오늘 열린 예약) → 지금 예약 받는 코트 | 지금 빈 시간 → 다음 예약 오픈
[알림 탭]   이 기기로 알림 받기 → 알림 기록(최근 24시간) → 알림 받을 테니스장 → 언제 알려 드릴까요 → 테스트 알림
[더보기 탭] 이렇게 써요(3단계) · 색깔 뜻 · 친구에게 공유 · 홈 화면에 추가하는 방법 · 정보는 어디서 오나요
[아래 탭 줄] 홈 · 알림(새 알림 수) · 더보기
```

- 주소: `#hannam #jangchung #maru #sunwoo #forest #jamwon #daechi #play(반포) #alerts #more`. 알림을 눌러 들어오는 `#play` 는 반포 화면.
- 뒤로 가기는 실제로 지나온 화면을 따른다. 한 곳 → 다른 곳은 이력을 쌓지 않아 뒤로 한 번이면 전체. 알림으로 한 곳에 바로 들어오면 뒤로 가면 전체.
  아래 탭 `홈`은 다른 탭에서 누르면 보던 테니스장으로, 홈에서 누르면 전체로 간다. 뒤로 돌아오면 스크롤 자리를 되살린다.
- **열고 닫기**: 카드의 `[코트 예약 보기]`를 누르면 그 테니스장이 열리고, 같은 자리의 `[코트 예약 닫기]`를 누르면 닫힌다(보던 자리로 돌아온다).
  고르기 줄에서 열려 있는 테니스장을 한 번 더 눌러도 닫힌다. `‹ 전체 테니스장`(뒤로) 버튼과 휴대폰의 뒤로 가기도 그대로 쓴다.
- 고르기 줄의 점: 빨강 = 새 알림 · 초록 = 오늘 예약이 열림 · 주황 = 24시간 안에 열림.
- 정렬(전체에서만, 기기에 기억): `가나다순`(늘 같은 자리) · `예약 받는 곳 먼저` · `빨리 열리는 순`. 같으면 가나다순.
- **테니스장 순서는 어디서나 가나다순**이다(고르기 줄 · 카드 · 알림 탭의 테니스장 목록). 반포도 맨 끝이 아니라 제자리(마루공원 다음)에 온다.
  서버가 주는 순서(`WATCH_KEYWORDS`)와는 상관없이 화면에서 `byArea` 로 정렬한다(한글은 글자 코드 순서가 가나다순).

## 4. 테니스장 카드 — 모든 곳이 같은 모양

```
┌──────────────────────────────────────────────┐
│ [코트 그림]  장충테니스장                  (종) │
│             중구 · 하드 코트  [새 알림]         │
│ ● 오늘 09:00에 예약이 열렸어요. 빈자리는 …      │  ← 안내 한 줄(있을 때만)
│ ┌───────────────────┐ ┌────────────────────┐ │
│ │ 지금 예약           │ │ 다음 예약 오픈        │ │
│ │ ● 예약 받는 중      │ │ 11.25(수) 10:00     │ │
│ │ 코트 2개           │ │ 10일 남음 · 공지 일정 │ │
│ └───────────────────┘ └────────────────────┘ │
│ [            코트 예약 보기  ⌄            ]    │
└──────────────────────────────────────────────┘
```

- 카드 어디를 눌러도(종 빼고) 그 테니스장이 열린다. 종은 그 테니스장 알림을 켜고 끈다(버튼 둘이 겹치지 않는다).
- **안내 한 줄**(카드 안, 맨 위 큰 카드 대신): 오늘 예약이 열렸으면 초록 `오늘 09:00에 예약이 열렸어요. 빈자리는 예약 화면에서 확인해요.`,
  공지된 오픈 시각만 지났으면 노랑 `공지된 오픈 시각(09:00)이 지났어요. 예약 화면에서 확인해 보세요.` 그 밖에는 없다.
- 화면이 아주 좁으면(약 336px 아래) 두 칸이 위아래로 놓인다.

### 4.0 코트 그림 — 바닥 종류

위에서 본 코트를 바닥 종류의 색으로 그린다: 인조잔디 = 줄무늬 초록 · 하드 = 파랑 · 클레이 = 주황. 두 종류면 반반, 모르면 회색(글자도 적지 않는다).
바닥 종류는 **공개된 시설 안내에서 확인한 것만** 적는다(`SURFACE` — 공사로 바뀌면 이 표와 코드의 한 줄만 고친다).

| 곳 | 바닥 | 확인한 곳(2026-11-15) |
|---|---|---|
| 한남 | 인조잔디(12면) | 예약 정보 사이트 seoul-tennis.com 의 바닥재 표기 |
| 장충 | 하드(우레탄, 9면) | 같은 사이트(목록 '하드코트', 상세 '우레탄') |
| 마루공원 | 인조잔디(3면) | 서울물재생시설공단 안내 '인조잔디(실외)' + 같은 사이트 |
| 선우공원 | 인조잔디(3면) | 같은 사이트 |
| 서울숲 | 인조잔디 | 서울시 공개 API 의 시설 안내문 '시설현황 - 인조잔디' |
| 잠원 | 클레이 | 예약 정보 사이트 표기('클레이 6면, 예약 운영 1~3번, 표면 확인 필요') + 사용자가 알려 준 내용 |
| 대치유수지 | 하드(3면) | 예약 정보 사이트 표기 + 사용자가 알려 준 내용 |
| 반포 | 인조잔디 | 사용자가 알려 준 내용(2026-11-15). 서초구 이용안내에는 '인조잔디 8면 · 클레이 4면'으로 적혀 있지만 예전 내용 |

### 4.1 `지금 예약` 칸 — 위에서부터 먼저 맞는 것

상태·수량은 **서버 원본**으로 판정한다(겹치는 코트를 빼기 전).

| state | tone(색) | 큰 글자 | 작은 글자 | 조건 |
|---|---|---|---|---|
| hot | go(초록, 깜빡이는 점) | 오늘 열림 | `09:00 시작 · 코트 11개` | 서울시 자료의 예약이 오늘 열렸고 2시간이 안 지남(`expected` 아님) |
| open | go | 예약 받는 중 | `코트 2개` | `available` 에 코트가 1개 이상 |
| check | warn(노랑) | 확인 필요 | `09:00 공지 시각 지남` | 시설 공지의 오픈 시각이 지났는데(2시간 안) 서울시 자료에 새 예약이 없음 |
| check | warn | 확인 필요 | `예약 화면에서 확인` | `closed` 코트 가운데 상태 `unknown`(열렸지만 상태가 안 올라옴)이 있음 |
| wait | off(회색) | 예약 시작 전 | `열리는 날을 기다려요` | 코트 자료는 없고 다음 오픈만 있음 |
| none | off | 정보 없음 | `올라온 예약이 없어요` | 아무 자료도 없음 |
| full | off | 모두 마감 | `코트 9개`(마감 코트 수) | `closed` 에 `full` 이 있음 |
| ended | off | 예약 끝남 | `다음 오픈을 기다려요` | `closed` 가 전부 `ended` |
| paused | off | 잠시 멈춤 | `시설 사정으로 멈췄어요` | `closed` 가 전부 `paused` |
| closed | off | 예약 안 받는 중 | `다음 오픈을 기다려요` | 그 밖(끝남 + 일시중지가 섞임) |

코트 상태는 `court.state`, 없으면 묶음의 `state`.
수량 표기 `courtsLabel`: 번호·글자로 시작하는 코트만 있으면 같은 코트(조명 예약 포함)를 한 번만 세어 `코트 N개`, 번호 없는 예약이 섞이면 `예약 N건`.

반포(테니스플레이 — 날짜·시간별 빈 코트를 실제로 안다):

| state | tone | 큰 글자 | 작은 글자 |
|---|---|---|---|
| free | go(자료가 `stale` 이면 warn + `오래된 정보 · `) | 빈 시간 있음 | 가장 이른 빈 시간 `오늘 20~22시`(다른 시간·날이 더 있으면 ` 외`) |
| full | off | 빈 시간 없음 | `11.15~11.22 확인`(확인한 날짜 범위) |
| loading | off | 불러오는 중 | `잠시 뒤 다시 열어 주세요` |
| error | off | 확인 못 함 | `테니스플레이에서 확인` |

### 4.1-1 서울시 자료에 없는 곳 — 대치유수지체육공원

강남구청이 자체 예약 사이트로 운영해서 서울시 공개 자료에 없다. 그 사이트를 자동으로 읽지 않는다(매크로 제한 안내가 있는 예약 사이트).

- `지금 예약` 칸: state `ext` · 회색 · `직접 확인` / `예약 사이트에서 봐요`. 예약 상태를 지어내지 않는다.
- `다음 예약 오픈` 칸: 시설 누리집의 대관 안내에 적힌 정기 일정 **'월 예약의 기준일은 매월 셋째 주 월요일 09:00'** 으로 서버가 계산한다
  (`app/services/notice.py` 의 `STATIC` — 공지 일정과 같은 길로 화면·알림에 나간다. 전날 · 1시간 전 알림도 같다).
- 한 곳 화면: `지금 예약` 구역에 "여기서는 예약 상태를 볼 수 없어요" + `[대치유수지체육공원 예약 사이트 열기]`(사람이 누르는 링크) + 그 사이트에 적힌 예약 방법.
- 모델에서는 `kind: 'ext'`(`EXTERNAL` 에 적힌 곳). 서버에서는 `openings.STATIC_PLACES` 가 이름·지역을 준다.

### 4.2 `다음 예약 오픈` 칸

| state | 큰 글자 | 작은 글자 | 조건 |
|---|---|---|---|
| date | `오늘 09:03` · `내일 09:00` · `11.25(수) 10:00` | 남은 시간(`8초 남음` · `23시간 58분 남음` · `10일 남음`), 공지 일정이면 ` · 공지 일정`. 24시간 안이면 `soon = true`(주황) | 아직 안 열린 예약 가운데 가장 이른 것 |
| always | 따로 없음 | `정해진 날이 없어요` | 다음 오픈이 없고, `available`·`closed` 에 상시 예약 묶음(`until_kind` 가 빈 값, 지난 회차 아님)이 있음 |
| unknown | 아직 몰라요 | `지난번 10.27(화) 09:30` 또는 `일정이 아직 없어요` | 그 밖 |

반포: `play.next_open.at` 이 미래면 date, 아니면 unknown(이용일 `next_open.date` 는 있으면 설명에만 쓴다).
반포의 날짜·시각은 순서대로 정렬한 뒤 가장 이른 것을 고른다(서버가 순서를 지키지 않아도 맞게).

## 5. 한 곳 화면 — 구역 순서는 늘 같다

1. **오늘 열린 예약**(있을 때만) — 몇 시에 열렸는지, 코트 버튼, "이미 찬 코트도 있을 수 있어요".
   공지 시각만 지난 경우 제목은 `공지된 오픈 시각이 지났어요`, 지난번 코트로 예약 화면에 들어가 확인하게 한다.
2. **지금 예약 받는 코트** — 묶음(이용 기간 · 신청 마감)별 코트 버튼(무료/유료 · 조명 · 요일 · 시간 표시는 v5 그대로). 누르면 서울시 예약 화면(새 창).
   없으면 `지금은 예약 받는 코트가 없어요`. 그 아래 접어 둔 `마감된(예약 받지 않는) 코트·시간대 n건 보기`.
   반포는 **지금 빈 시간** — 시간대(전체·오전·오후·저녁) + 날짜 줄(누르면 시간별 빈 코트 번호) + `테니스플레이에서 예약하기` + `빈 시간이 생기면 알림` 스위치.
3. **다음 예약 오픈** — 날짜·시각 크게, 남은 시간, 이용 기간·코트 수(공지 일정이면 규칙 + "바뀔 수 있어요"), `열리는 코트 미리 보기`, 그 뒤 오픈들, 지난 오픈 날짜(최대 3개), 큰 버튼 `열리기 전에 알림 받기`.

## 6. 맨 위 큰 카드 — 없앴다

처음에는 전체 화면 맨 위에 '다음 예약 오픈 / 오늘 열린 예약'을 크게 보여 주는 카드가 있었다. 올린 날 사용자 의견("더 불편하다, 그냥 테니스장 옆에 안내해 달라")으로 없앴다.
같은 내용은 테니스장 카드 안에 있다: 두 칸(`지금 예약` · `다음 예약 오픈`) + 안내 한 줄(§4) + 고르기 줄의 점(§3).
맨 위 카드 자리는 불러오는 중 · 연결 오류 · 서울시 자료를 아직 못 받았을 때만 쓴다.

## 7. 알림

- **종 = 그 테니스장의 예약 오픈 알림**(반포 포함, 모든 곳이 같은 뜻). 카드 · 한 곳 머리 · 큰 카드 · 큰 버튼 · 알림 탭의 테니스장 줄이 모두 같은 것이고, 지금 실제로 받는 곳만 켜짐으로 보인다.
  - 꺼진 기기에서 누르면 알림을 켠다. 한 번도 켠 적 없는 기기는 **그 곳만**, 전에 쓰다 끈 기기는 **전에 고른 곳 + 그 곳**.
  - 켜진 기기에서는 그 곳을 더하거나 뺀다. 받을 것이 하나도 안 남으면 알림 전체를 끄고 "받을 곳이 없어 알림을 모두 껐어요"라고 알려 준다.
  - 서버 등록까지 끝나야 켜짐으로 보인다. 결과는 토스트로 알려 준다(범위 · 알림 시점 · "이번 오픈은 알림 시간이 지났어요").
- **반포 빈 시간 알림**(누가 취소해서 자리가 나면)은 따로 켜고 끈다 — 반포 화면의 스위치와 알림 탭의 스위치.
- `이 기기로 알림 받기` 스위치: 켜면 전에 고른 곳(처음이면 5곳)을 받는다. 끄면 고른 것은 기억해 둔다.
- 아이폰 Safari(홈 화면에 추가 전)·앱 안 브라우저에서는 켤 수 없다 → 종을 누르면 알림 탭의 설치 안내로 간다.
- 새 알림: 앱 알림(서비스워커 보관함) + 서버의 보낸 알림 기록(`/board` 의 `feed`). 홈 맨 위 띠 · 카드와 고르기 줄의 표시 · 아래 탭 `알림`의 숫자로 보인다(v5.7 규칙 그대로 — 본 지 10분 넘은 것은 앱을 다시 열 때 사라진다).
  알림 탭의 `알림 기록`은 서버가 최근 24시간에 보낸 알림 가운데 이 기기가 받기로 한 것 + 새 알림.

## 8. 말투 규칙

- 한 줄에 한 가지, `~해요` 체. 뜻이 먼저, 길이는 그다음.
- 쓰는 말: 예약 받는 중 · 모두 마감 · 오늘 열림 · 잠시 멈춤 · 다음 예약 오픈 · 남음 · 알림 받기 · 빈 시간 · 코트 N개.
- 안 쓰는 말: 접수중/회차/상태 미갱신/D-10/상시/미정 같은 행정·한자 용어(설명 문장 안의 `접수 상태` 정도만 허용).
- `예약 받는 중`은 "빈자리 있음"이 아니다 → 전체 화면과 한 곳 화면에 `날짜별 빈자리는 서울시 예약 화면에서 확인해요`를 적는다.

## 9. 모양 규칙(토큰)

- 바탕 회색 + 흰 카드(모서리 20px). 글꼴 Pretendard. 숫자는 고정 폭.
- 색 뜻은 하나씩: 초록 = 지금 예약 받음(반포는 빈 시간 있음) · 주황 = 24시간 안에 열림 · 노랑 = 확인 필요 · 회색 = 안 받음/정보 없음 · 빨강 = 새 알림.
  색만으로 말하지 않는다(점 + 글자). 글자 대비 4.5:1 이상.
- 누르는 곳은 높이 44px 이상. 큰 버튼 52px.
- 큰 카드는 로고 색(짙은 초록 + 라임 공).

### 10.1 `buildVenues(d, now)` 계약

입력: `/board` 응답 `d`, 지금 시각 `now`(ms, `nowMs()` 와 같은 값). 출력:

```
{
  list: Venue[],        // 가나다순: 대치유수지·마루공원·(d.play 가 객체면) 반포·서울숲·선우공원·잠원·장충·한남
  hot: Opening[],       // 오늘 열린 지 2시간이 안 된 예약(시각 순, 공지 일정 포함)
  next: Opening|null,   // 5곳에서 아직 안 열린 예약 가운데 가장 이른 것
}
Venue = {
  area, name, region, kind: "seoul" | "ext" | "play",   // ext = 서울시 자료에 없는 곳(§4.1-1)
  now:  {state, tone: "go"|"warn"|"off", title, sub},                       // §4.1
  next: {state: "date"|"always"|"unknown", at, title, sub, expected, soon}, // §4.2
  hot: Opening[], cold: Opening[], upcoming: Opening[],                     // cold = 오늘 열린 지 2시간 이상
  avail: Group[], shut: Group[],                                            // 보여 줄 목록 — hot 에서 보여 준 코트는 뺀다(예약 주소 기준)
  past: string[], rule: string, play: object|null,
}
```

걸러내기 규칙(v5 `renderBoard` 그대로):

- `openings`: `open_at` 이 올바른 것만. `opened = 서버 표시 || open_at <= now`. 열린 것은 오늘 것만.
  hot = `opened && now - open_at < 2시간`(정확히 2시간이면 hot 아님).
  공지 일정(`expected`)은 열린 지 2시간이 지나면 버린다. 공지 일정이 열린 경우 코트는 그 곳 `closed` 의 `ended` 코트로 채운다.
- 같은 예약 주소(`reserve_url`)가 hot 에 있으면 `avail`·`shut`(보여 줄 목록)에서 뺀다. **상태·수량 판정에는 빼기 전 원본을 쓴다.**
- **새 예약이 올라와 있는 곳에서는 접수가 끝난(`ended`) 지난 예약 묶음을 뺀다**(목록에서도, 상태 판정에서도). 지난 예약의 이용 기간 마지막 날이 오늘이면
  서버 자료에 하루 동안 둘이 같이 오는데, 화면에 겹쳐 나오면 헷갈린다. '새 예약이 올라와 있다' = 접수 중인 코트가 있거나, 끝나지 않은 묶음이 있거나, 오늘 실제로 열린 예약이 있다.
  새 예약이 없는 곳은 지난 예약을 그대로 둔다(그 코트로라도 예약 화면에 들어가 볼 수 있게).
- 잘못된 값(null, 배열 아님, 틀린 날짜)은 조용히 뺀다. 응답 자체가 객체가 아니어도 5곳은 항상 나온다.
  11월 31일처럼 없는 날짜도 틀린 날짜다(`kstMs` 가 NaN).
- 다시 그리는 때: 자료가 바뀜 · 예약이 열리는 시각 · 열린 지 2시간 · 24시간 안으로 들어오는 시각 · 자정.

`sortVenues(list, key)`: `base` 그대로 · `now` hot(0) → tone go(1) → warn(2) → off(3) · `soon` `next.at` 이른 순(date 가 아니면 맨 뒤). 같으면 원래 순서.

시험: `tests/js/venue_harness.js`(계산 부분만 떼어 Node 로 실행, 실제 응답 `tests/js/fixtures/board_live_20261115.json`) · `tests/js/venue_model_cases.js`(Codex 가 이 문서만 보고 쓴 독립 시험 100건) · `tests/test_venue_model.py`(둘을 pytest 로 실행).

### 검토 1에서 받아들인 것

- 수량은 코트 수(같은 코트 한 번만)로, 셀 수 없으면 예약 건수로(P1-1). `면` → `개`.
- "열림 ≠ 빈자리": `방금 열림` → `오늘 열림`, 큰 카드·한 곳 화면·전체 화면에 "빈자리는 예약 화면에서 확인" 문구(P1-2).
- 오늘 열린 예약이 있어도 24시간 안의 다음 오픈을 큰 카드에 늘 같이 표시, 여러 곳이 열리면 줄로 모두(P1-3).
- 상태·수량은 원본으로 판정하고 겹침 빼기는 보여 줄 목록에만(P1-4).
- 실제 예약 받는 중이 공지 시각 지남보다 먼저, `예약 시작 전` · `예약 안 받는 중` 상태 추가, 상시 예약 판정에 마감 묶음도 포함(P1-5).
- 종의 범위: 반포 종도 오픈 알림 하나만(빈 시간 알림은 따로), 끈 기기는 전에 고른 곳을 보존, 마지막 해제 시 안내(P1-6).
- 등록이 끝나야 켜짐 표시, 알림 시점이 지난 오픈 안내(P1-7).
- 오래된 정보 띠(20분), 반포 `stale` 은 초록보다 먼저, 빈 시간 없음은 확인한 날짜 범위로(P1-8).
- 쉬운 말(`10일 남음` · `따로 없음` · `아직 몰라요`), 칸 이름 `지금 예약` · `다음 예약 오픈`(P2-9).
- 공지 일정 옆에 규칙과 "바뀔 수 있어요"(P2-11), 실제 이력을 따르는 뒤로 가기(P2-13), 겹치지 않는 버튼·이름과 상태를 읽어 주는 종(P2-14), 좁은 화면에서 두 칸 세로 배치(P2-15), `알림 기록` 이름과 설명(P2-16), 큰 카드 버튼에 목적지 이름(P3-17).

### 받아들이지 않은 것(이유)

- 테니스장 고르기를 별도 목록 화면으로(P2-12): 전체 화면이 곧 6곳 목록이라 한 번 더 누르게 하지 않았다. 고른 곳은 가운데로 끌어와 보여 준다.
- 한 곳 화면에서 임박한 오픈을 코트 목록보다 앞에(P1-3 일부): 구역 순서를 늘 같게 두고, 머리 카드의 주황 칸으로 맨 위에서 보여 준다.
- 반포 자료가 없는 서버에서도 6곳 유지(P1-8 일부): 반포 조회를 켜지 않은 서버에는 반포가 아예 없다(카드도 없음). 조회가 실패한 경우에는 카드가 `확인 못 함`으로 남는다.

### 검토 2에서 받아들인 것

독립 시험 100건 가운데 7건이 실패했고, 모두 구현 쪽 결함이라 고쳤다(기대값은 그대로 두었다).

- 응답이 `null` 이어도 5곳을 그린다(P1-3, 4건).
- 반포의 '가장 이른 빈 시간'은 날짜·시각을 정렬한 뒤 고른다(P2-1).
- 반포 다음 오픈은 `next_open.at` 만 미래면 보여 준다(P2-2).
- 11월 31일처럼 없는 날짜는 틀린 날짜로 뺀다(P2-3).
- 빈 시간 알림을 끄다 실패하면 설정을 바꾸지 않는다. 끄지 못한 사실을 홈에서도 토스트로 알린다(P1-1).
- 서버 등록에 실패했는데 "켰어요"라고 하지 않는다 — 등록까지 끝나야 성공 안내, 실패하면 뒤에서 다시 등록(P1-2).
- 다시 그려도 키보드 초점이 같은 버튼에 남는다(P2-4). 24시간 안으로 들어오는 때에도 다시 그린다(P2-5).
- 오늘 열린 지 2시간이 넘은 예약은 예약마다 시각·이용 기간을 한 줄씩 남긴다(P2-6). 지난 반포 오픈을 '오픈 전'으로 보여 주지 않는다(P2-7).
- 서비스워커 준비를 12초까지만 기다린다(P2-8). 고르기 줄·정렬·새로 고침 버튼 높이 44px(P2-9).
- 색 설명에서 서울시와 반포를 나눠 적는다, 상시 예약 문구 `정해진 날이 없어요`(P3-1). 알림 시점은 이 기기에서 고른 것만 말한다, `잠시 멈춤`(P3-2). 새 알림이 있는 고르기 버튼에 읽어 주는 이름(P3-3).

독립 시험에서 바꾼 기대값은 위 문구 두 곳(`정해진 날이 없어요` · `잠시 멈춤`)뿐이다 — 검토 2의 제안으로 기준서를 고친 자리다.

  - 이력은 바꿔 끼운다(`replaceState`) — 뒤로 가기는 늘 전체 목록으로, 보던 자리로 돌아간다.
  - 다음 카드가 있던 자리에서 맨 위로 미끄러져 올라간다(Web Animations 0.34초, 움직임 줄이기 설정이면 없음).
  - 계산: `nextVenue(list, key, area)`(모델) · 동작: `stepNext()` · `checkStep()`. 시험: `tests/test_venue_model.py`.
- **서울시 예약 화면에서 빈자리 찾는 법**: 사용자가 로그인한 어사이드 브라우저로 서울시 예약 화면을 사람 속도로 열어 확인했다(11/17, 한남 1번 코트 평일 주간. 앱은 여전히 그 사이트를 자동으로 읽지 않는다).
  - 코트 상세 화면(앱이 여는 화면)의 달력이 새 디자인으로 바뀌어 **마감된 날(2/2)도 빈 날(4/6)과 같은 흰색**이다. 회색은 회차가 없는 날뿐.
  - 숫자는 화면의 설명 글(`모집정원/잔여정원`)과 달리 **예약된 수/전체 수**다(11/19 `4/6` → 회차 6개 중 4개가 찼다).
  - `[예약하기]` 다음 화면(로그인 필요)의 달력은 예전 디자인 그대로 — 예약할 수 없는 날은 회색, 빈 날은 흰색. 회차는 `(0/1)` 빈 시간 · `(1/1)` 찬 시간.
  - 앱: `지금 예약 받는 코트` 구역 아래에 접힌 안내 `서울시 예약 화면에서 빈자리 찾는 법`(`HOWTO_BODY`), 더보기에도 같은 글. 코트 아래 한 줄 안내도 숫자 보는 법으로 바꿨다.
